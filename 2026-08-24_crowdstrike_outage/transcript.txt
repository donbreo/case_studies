On Friday, July 19, 2024, at 4:09 a.m. Coordinated Universal Time ( UTC), cybersecurity company
CrowdStrike sent a small file to every Windows computer running its software. The file weighed about
40 kilobytes. This was not a program. This wasn't a code update. It was just configuration data, a
rules file. And after 78 minutes they called him back. And in those 78 minutes, 8.5 million Windows
computers around the world “ crashed” to a “blue screen,” then rebooted again and crashed again.
Thousands of flights were canceled. Delta Airlines was unable to operate for 5 days in a row.
Hospitals postponed scheduled surgeries. Banks have suspended operations. 911 emergency services
have stopped working in many US states . Sky News was interrupted in the middle of a live broadcast.
And at airports, passengers were given handwritten boarding passes . It was the largest IT failure
in the history of computer technology. Losses for Fortune 500 companies alone are estimated at $5.4
billion. And here's the craziest part. This was not a cyberattack. The file that caused this came
from the company that these machines paid for their protection. And if you trace everything back to
the kernel, to the driver, to the file, then the whole disaster comes down to one erroneous number.
It said 21, while the code should have returned 20. So the biggest failure in history was due to an

outside of the security field have never looked at it. Falcon from CrowdStrike is an EDR system.
This is an endpoint detection and response system . Think of it as an antivirus, but on steroids. It
doesn't just scan files for known signatures, it monitors every process running on the machine,
every open file, every network connection, and every message between processes. And when it sees a
pattern or attack behavior, it blocks that process in real time right during the attack. Think about
what this job requires. It requires three things. First, she has to see everything that happens in
the car. It must act before the malware is triggered, not after, and it must be invulnerable,
because the first step of any professional malware is to disable the security agent. All three of
these requirements point to one place—the core of the system. Every Windows machine has two modes .
You can perceive them as two separate worlds. User mode is where your applications run: Chrome,
Excel, your code, and each process has its own isolated memory. And if a process tries to access
someone else's memory, Windows simply kills that process, and everything else continues to run. But
kernel mode is the operating system itself. This is a scheduler, memory manager, drivers. There are
no walls in kernel mode. Everything has a common memory space and a single area of ​​trust. So what
happens when kernel code touches memory it shouldn't have access to? Windows does something that
most people don't even realize. She intentionally kills herself . A "blue screen" in Windows is not
a system crash. This is a design decision called "stop on failure." The logic is that if the kernel
state is corrupted, I can't trust anything anymore . My next write to the disk may destroy your
data. Therefore, the safest thing I can do is to stop immediately and turn off the entire machine,
including myself. This is what I want you to remember: any bug in any kernel driver from any
developer is inherently fatal to the entire machine. This is the agreement you sign when you enter
the core. And that's why Microsoft guards the entrance to the system kernel. To release a kernel
driver for Windows, you need to pass WHQL— Microsoft's hardware quality validation program . Your
driver is tested, certified, and cryptographically signed by Microsoft. This process takes weeks.
Kernel code should be sparse, stable, and immutable. But now let's look at CrowdStrike's business.
Attackers change tactics daily, sometimes even hourly. If a new attack method emerges this morning,
CrowdStrike customers expect to see it detected today. This, in fact, is the product itself. This is
the reaction speed. But here a conflict arises. The detection logic should change daily, and it
should work where the code is "frozen" due to long certification . So, how do you deliver daily
logic updates to a place where the code can't change? You separate the engine from the fuel, like
they do in rocket technology. The driver, a file called CS agent.sys, is an engine that is certified
and signed by Microsoft only once. Inside this driver, CrowdStrike created an interpreter—a content
processing mechanism. So the actual detection logic is delivered separately as data, and CrowdStrike
calls them channel files. The driver reads and interprets them, changing its behavior without
changing a single byte of the signed code. This system consists of two parts. You need to understand
both to continue watching the video. The first is the template types, which are essentially code.
They are located inside the sensor, and each one monitors a specific category of behavior, such as
process creation, file writing, or network activity. So, template types are shipped in a slow
certified path along with sensor releases. The second part is the template instances, which are
essentially data. These are specific rules, templates for compliance within this category. They are
supplied as channel files. They are updated constantly because it is the fastest way. This solves a
very real problem. The CrowdStrike core driver can only change a few times a year because each
release must be tested, signed, and carefully deployed . But new attack methods appear constantly,
sometimes several times a week. If CrowdStrike had to release a new driver every time to detect a
new attack, they wouldn't have time. Therefore, the driver remains almost unchanged, and the
detection rules are updated separately as channel files. Thus, the mechanism changes slowly, while
the detection can change rapidly. And this is not unusual. This is how most modern endpoint
protection products work . The industry needs a fast way to respond to new threats within hours
without releasing new kernel code every time. There is one more detail. Channel files have numbers.
File 299, for example, defines how the sensor evaluates named pipes, similar to Windows pipes for
interprocess communication. Attackers love named channels. Frameworks like Cobalt Strike use them to
move around invisibly and communicate with control systems. So 291 is an important file that changes
frequently. And remember this number: file 291. So CrowdStrike is distributing two types of updates,
and they go in two very different directions. The slow path is sensor releases, that is, the code
itself. They are released after full testing. CrowdStrike first launches new versions on its own
machines, then gradually deploys them, and customers control the versions themselves. Companies
actually appreciate this feature. As an enterprise, you can configure your own fleet of machines to
use versions n -1 or n-2, deliberately lagging behind by one or two versions to let the rest of the
world find bugs for you. And the fast way is quick response content, that is, channel files. So, a
new instance of the template is validated by a single automated gateway—a cloud service called a “
content validator.” If it passes the test, it is immediately sent to the entire server fleet, to
each client, to each machine. So let me repeat that, because this is the most important part of the
entire video. Customers, such as large companies, could control the deployment of new versions of
sensors. Many of them deliberately stayed one or two versions behind so as not to be first in line
for a failed update. But these controls only applied to the sensor itself. Channel files are a
different matter. After the channel file passed through CrowdStrike's verification pipeline, it was
distributed worldwide. Companies that believed they were doing a phased update received the new
content immediately, just like everyone else, even if they chose sensor version n-1 or n-2. So in
practice there were two update systems. One was gradual and client-controlled, the other was

Because in 2019, Apple kicked everyone out of the kernel, deprecated kernel extensions, and forced
security software developers to use a user- space API—the Endpoint Security Framework. The kernel
broadcasts events to the security agent, which runs as a regular process. So, on a Mac, if Falcon

Zelkova—a theorem prover that checks every possible query against an S3 bucket's policy. And the

testing on examples, but proving the correctness of all execution paths. The very class of bugs that

because of regulatory requirements. In 2009, Microsoft promised European regulators that security
